Production guide · researched October 6, 2026

Make Kitty move.
No camera required.

Use code to animate the story, existing Kitty artwork to give it character, and captions to make every scene understandable. Your laptop is the studio. Friends can help from wherever they are, whenever they are free.

Open the motion study Set up the local workflow

Start with the included HTML motion study

The recommended first cut is a 90-second animated explainer: SVG shapes, Kitty cats, three friends, clear terms and a simple contribution-to-payout sequence. Codex or Claude Code edits the source; a browser renders each exact frame; FFmpeg assembles the MP4. No actor, location, screen-recording performance or video-generation subscription is needed.

Know what you are making. The motion study is an illustrated explanation with sample data. It does not execute payments. A polished animation can explain Kitty; it cannot prove a passkey worked, a transaction settled or another device recovered an account. Keep “Illustrated demo · sample data” visible, and retain test-dollar labels wherever amounts appear.

A small circle of friends, drawn in Kitty's own style

Use three named cat portraits around one shared pot. Each contribution follows a short path toward the center; the recipient's turn becomes clear through position and a written label. End with a completed record. The visual metaphor is shared commitment, not a country, village, costume or invented family history.

  • Ink #32232D
  • Pink #AD245F

What stays consistent

  • Bricolage Grotesque for titles, Figtree for reading. Reuse local licensed font files and existing logo/cat artwork.
  • One sentence and one main action per scene. Keep amounts and payment states readable; no rolling balance counters.
  • Use the same three names and coat colors throughout. Choose real names with permission or neutral sample names; nationalities need not appear.
  • A narrow text column plus a large visual in landscape. Stack them deliberately for portrait; do not crop a wide render.

Motion that explains

  • Plan 0.25–0.5-second transitions and at least 2–4 seconds to read a short caption. These are editing targets, not measured user research.
  • Connect money movement to a visible “Paid” or “Next recipient” label. Do not make value appear from decorative sparkle.
  • Keep the mascot out of authentication sheets, payment confirmations and errors, as the app guide requires.
  • Expose play, pause and scrub controls in HTML. Respect reduced motion for default playback; export stills for a static alternative.

The script artifact supplies alternate final cuts; timeline.js owns the included motion study's narration and timing. The opening should answer “Why save together?”, the middle “How does a round work?”, and the ending “What can I try today?”. Bidding, missed contributions and recovery belong in the longer product or sponsor cut, where their conditions have room to be explained.

Set up once, then work scene by scene

The commands below target this Linux checkout. They are setup instructions, not a claim that dependencies were installed or an account was funded. On this machine, Node 24, FFmpeg, Codex and Claude Code were found during the documentation review. Use the coding assistant you already have access to; buying both does not improve this workflow.

1. Open the folder and check the tools

cd /home/vedansh/Desktop/Hackathons/Kitty
node --version
ffmpeg -version
codex --version
claude --version

Node 24 or newer matches the repository's declared requirement. If a tool is missing, have the agent identify your operating system and propose the specific installation. For another machine, official instructions are available for Codex, Claude Code and FFmpeg. The native Claude installer is currently recommended; an existing working installation does not need replacing.

2. Preview the artifact before installing a video framework

Open animatic.html directly in a browser. Play it, pause it and scrub. An exact time can be reviewed with ?t=30. Use this to approve the wording and visual order before spending time on a full render.

For a local HTTP preview, serve only the documentation folder. In one terminal:

python3 -m http.server 4175 --bind 127.0.0.1 --directory docs

Then open http://127.0.0.1:4175/demo/animatic.html. Leave that terminal open while previewing; Ctrl+C stops it. This is local preview, not publication.

3. Ask your assistant to prepare the first cut

cd /home/vedansh/Desktop/Hackathons/Kitty
codex

Or run claude in the same directory. Paste the build prompt below. Give the agent the real file paths, the one scene to change and an observable result. Both CLIs can work in an existing repository; local CLI help was checked for this guide, alongside the Codex documentation and Claude quickstart.

4. Export a short draft before the whole film

Use the included renderer's help for its dependency check and exact supported options:

node docs/demo/render.mjs --help

Install the renderer tools in a separate temporary folder, leaving the app dependencies alone. Keep the generated package-lock.json with an archived project if you need reproducible exports later.

npm install --prefix /tmp/kitty-motion-tools playwright
/tmp/kitty-motion-tools/node_modules/.bin/playwright install chromium
node docs/demo/render.mjs --out output/kitty-motion/draft.mp4 --duration 5 --fps 12
node docs/demo/render.mjs --out output/kitty-motion/kitty-silent.mp4 --width 1920 --height 1080 --fps 30 --duration 90
node docs/demo/render.mjs --out output/kitty-motion/kitty-portrait.mp4 --width 1080 --height 1920 --fps 30 --duration 90

The default resolution is 1280×720. Use that for review on a modest laptop. Each export also writes matching SRT and VTT files beside the MP4. The exporter refuses to overwrite existing outputs; choose a new filename for each revision. It streams frames to FFmpeg rather than storing thousands of images.

If Playwright is installed elsewhere, set KITTY_PLAYWRIGHT_ROOT to its node_modules folder. To use an installed Chrome binary, set KITTY_BROWSER_EXECUTABLE. This checkout also has an existing preview-tools installation:

KITTY_PLAYWRIGHT_ROOT=/tmp/kitty-ui-preview/node_modules KITTY_BROWSER_EXECUTABLE=/usr/bin/google-chrome node docs/demo/render.mjs --out output/kitty-motion/local-draft.mp4 --duration 5 --fps 12

If setup fails: “Executable doesn't exist” means Chromium still needs installing; “FFmpeg missing” means its executable is not on PATH. In a restricted assistant sandbox, a Chrome socket-permission error requires approval to run the local renderer outside that sandbox. A temporary dependency folder can disappear after cleanup, so rerun the two install commands when needed.

The editable source is animatic.html, motion.css, motion.js and timeline.js. The bundled SRT and VTT describe this motion study's narration. Its timeline differs from the alternate polished explainer in the script book: choose one before generating a voice track. If you edit timeline.js, use the newly rendered subtitle files; regenerate the bundled caption downloads before sharing the HTML pack.

Render a five-second draft, inspect a still from each scene and both layouts, then render the full film. Fixed frame times, bundled fonts and image preloading make the result repeatable. Source files work offline; the coding assistant itself may need internet access.

5. Add real screen artwork only where it helps

The existing QA preview uses actual app components with mocked services. Its transactions are inert. It is useful for screen images, not for functional evidence. The current entry point documents this setup:

pnpm install --frozen-lockfile

If port 4174 already has an older preview running, start an independent one with KITTY_PREVIEW_PORT=4176 node app/qa/preview.mjs and use the printed port. Restart a preview after changing its mock names; the screen-source watcher does not reload the harness itself.

Use http://127.0.0.1:4174/?screen=Home, ?screen=Circle, ?screen=Me or ?screen=Cats. Take screenshots at a fixed viewport after fonts load. Keep a “Sample interface” label in the edit. The preview has only its declared screens and mock state transitions; a clickable button does not establish that a payment happened. Copy one at a time into Codex or Claude Code. Ask for artifacts and rendered evidence, not a list of ideas. Have one agent own the animation source while a reviewer checks screenshots; two writers should not edit the same scene simultaneously.

Build the illustrated cut

Read docs/demo/script.html, docs/demo/production.html, UI_GUIDE.md and the existing docs/demo/animatic.html. Use the included motion study and exporter as the base. Make a 90-second, camera-free Kitty explainer for friends saving together. Keep the agreed story and country-neutral wording. Use existing Kitty artwork, local fonts, #F8F6F7 paper, #32232D ink and #AD245F pink. Do not invent financial features or outcomes.

Animate HTML/SVG from a single explicit timeline time. No Date.now-based financial values, random state, network data, CSS animation clocks or real payment calls in the render. Keep sample-data and test-dollar labels visible. Preserve play/pause, keyboard scrub, reduced-motion behavior and fixed-time inspection. Finish landscape first and adapt portrait intentionally.

Edit one scene at a time. Save a still at its opening, middle and end. Render a five-second draft before the full film. Produce HTML review notes, MP4 and SRT/VTT captions; do not create new Markdown reports. Report the exact commands run and any part that was not verified.

Polish a scene without rewriting the story

Review the scene at [time in seconds] in docs/demo/animatic.html. The problem is [specific issue: text crowded / contribution path unclear / portrait overlap]. Keep the wording, amounts, timing, labels and existing Kitty design. Fix only this scene and its responsive layout. Check landscape and portrait at the same exact time, including long names. Show before/after stills and identify any changed file.

Prepare narration and captions

Take the approved narration from docs/demo/script.html. Create scene-numbered UTF-8 text files, a pronunciation list, a timed caption manifest and an HTML audio checklist under output/kitty-motion/. Expand AUSD as “A U S D” in the voice input where helpful, while retaining correct on-screen spelling. Use a calm, friendly delivery and leave pauses around financial amounts.

For now produce files only. If a paid stock-voice provider is selected later, generate one file per scene within the chosen budget and keep API keys outside source. Do not clone a participant's voice. After audio exists, measure each file and adjust captions to what is actually spoken; do not assume generated speech fits the planned timing. Export SRT and VTT alongside the captioned MP4.

Check the final cut as a skeptical viewer

Review the exported Kitty film at normal speed, then inspect stills around every scene boundary. Check caption timing and readability, amount consistency, names, spelling, disclosures, audio cutoffs, black frames, font loading, clipping and portrait composition. Confirm every live claim has an actual matching clip or record. A simulated passkey sheet, illustrative timer or mocked receipt is not proof.

Compare the film to docs/demo/script.html and docs/submission/index.html. Write a short HTML review with exact timestamps and fix material issues. Do not add results we did not observe or claim the video has been submitted.

Voice is optional. Readable captions are essential.

The zero-extra-cost version is silent and fully captioned. It needs neither a microphone nor an API key. Write captions as part of the scene, not as an afterthought. Export a separate subtitle file too, so a video host can expose accessible captions and translated tracks.

  1. Lock the narration. Make one text file per scene. For a 90-second edit, roughly 160–185 words leaves room for pauses; treat this as a planning estimate and time the actual voice.
  2. Generate or record short chunks. Keep the same narrator and settings. A friend can check names and pronunciation without appearing or speaking in the film.
  3. Fit the visuals to the voice. Place each clip at its scene start, listen for clipped words and add silence between ideas. Shorten the script if needed; avoid racing the voice through money terms.
  4. Time the captions to the audio. Use no more than two lines, approximately 32–42 characters per line as a starting point. Include relevant non-speech sounds. Review at phone size and with audio muted.
  5. Keep the track simple. Voice alone is sufficient. If using music, obtain a license for the actual use, retain its source and keep it quiet beneath speech. Mark synthetic narration in the credits/description.

After a correctly timed narration.wav exists, this optional FFmpeg command attaches it to a silent export. It pads short audio and ends with the video; listen first so a long narration is not cut off. Replace paths with the actual exported filenames.

ffmpeg -i output/kitty-motion/kitty-silent.mp4 \
  -i output/kitty-motion/narration.wav \
  -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 192k \
  -af apad -shortest -movflags +faststart \
  output/kitty-motion/kitty-narrated.mp4

The mapping and padding behavior follows the FFmpeg manual and apad filter documentation. This adds audio; it does not align sentences or rewrite subtitle timing automatically.

Let friends help asynchronously

Your friends can simply be themselves. The story does not require anybody to represent their country, perform an accent, share a home or pretend to be related. A three-person cast makes the explanation easy to follow; the contract currently permits 2–12 members, so three is a demo choice, not a minimum requirement.

No device or recording needed

  1. Send the HTML or a draft MP4 privately.
  2. Ask each person: “What do you think happens to the money?”, “What happens after my turn?”, and “Which line was unclear?”.
  3. Let them choose a display name or pseudonym and a cat. Request permission before using their name or feedback publicly.
  4. Keep a dated feedback note. Three friends provide early qualitative feedback, not market validation.

Optional actual testnet participation

  1. Use independent accounts and their own devices. Do not share a Google account, passkey or password to stage a group.
  2. Choose a schedule that accommodates time zones. They can record small screen-only clips separately; nobody needs a camera.
  3. Record the app version, chain, address, transaction hash and UTC time beside each clip.
  4. Label clips from separate takes. Mark shortened waits. Use the testnet runbook for any timed bidding/recovery test.

A cross-device recovery claim needs a real cross-device test. Use one tester's own synced passkey setup on devices they control. That is separate from three friends holding independent accounts. If a secure system prompt is blank in a screen capture, show the real transition and label the omitted system sheet. An animated fingerprint icon remains illustrative.

Optional screen-only testnet runbook

The animation does not need any of these steps. Use them later to obtain actual contract evidence or support a friend on a phone. Funding, creating, joining and playing a circle send testnet transactions. They are instructions to run deliberately; no network action is performed by opening this guide.

A laptop can fill the test seats

From the repository root, install dependencies. If services/.env does not already exist, copy services/.env.example to it. Set the documented RPC/service configuration without pasting keys into chat. Existing deployed contract addresses come from deployments/10143.json. Use the sponsor or a testnet-only CREW_FUNDER_KEY for gas.

pnpm demo:check
pnpm demo:crew init 3
pnpm demo:crew list
pnpm demo:crew fund
pnpm demo:crew create --names "Host,FriendA,FriendB" --amount 5 --every 120 --start 5 --offers 0 --title "Friday Circle"

demo:check is read-only. init writes local test keys and reads their state; fund and create submit transactions. The helper prints an invite for each remaining seat. Join those seats and let the crew complete the short practice:

pnpm demo:crew join 'PASTE_FRIEND_A_INVITE_HERE'
pnpm demo:crew join 'PASTE_FRIEND_B_INVITE_HERE'
pnpm demo:crew status CIRCLE_ADDRESS
pnpm demo:crew play CIRCLE_ADDRESS --close

Replace the uppercase placeholders; never run them literally. Keep invite links quoted because their fragments contain shell characters. Use actual circle and participant identifiers in the evidence record. play --close pays for eligible crew accounts, closes rounds and collects at the end. It is not a native passkey test.

Fresh defaults are Host, FriendA and FriendB. An existing services/.crew.json retains its original names and keys; nothing is renamed. The helper can assign an available account when a matching name is absent. Check list, join output and status to map accounts to seats. Use --as EXISTING_NAME only for an account already in that local file. Keys live in the gitignored crew file: do not publish it.

One phone plus two helpers

Create the circle in the actual app, invite your friends or join two seats with the helper, and record only the app screen. For the main demo use three members, $5, Every 10 min, In 30 min and earning off. Keep offers off until the simple cycle works. Start pnpm demo:watch --circle CIRCLE_ADDRESS --name Host=PUBLIC_ADDRESS in another terminal to retain matching indexer observations.

For the optional offer/miss story, create a separate circle with Host, Friend B, Friend A in the intended order; inspect the actual standing-based order. Enable offers up to 30%. Both not-yet-paid-out members must be eligible when the offer is committed. In round 2, Friend A contributes and offers 10%; Friend B skips the payment on purpose. Never infer that a prior miss leaves an account eligible for the next rehearsal.

If the original device cannot provide a passkey sheet in a screen recording, keep the real before/after sequence and caption the omitted secure prompt. Do not invent a successful prompt.

When a rehearsal stalls

  • No gas or faucet cooldown: read the preflight output and fund test accounts ahead of time; sponsor caps can be shared by an IP address.
  • No offer button: check the commit window, unpaid status, standing and the number of eligible members.
  • Round waiting: keep the app open, tap the available close action, or run the keeper with a funded testnet key.
  • Join window expired: use the cancellation/refund path and start a new practice with enough joining time.
  • Restore incomplete: verify the same passkey and network services. Record a failure honestly; an animation cannot turn it into a pass.

Collect remaining balances when the test circle finishes. Keep original captures and public receipt IDs, then cut them asynchronously into the product or sponsor video. No camera or shared location is needed.

When to graduate to Remotion

Move only when you need richer audio sequencing, repeated versions or a larger scene library. A Remotion composition names the video and defines width, height, frame rate and duration; its React components calculate what to draw at each frame. This fits a coding agent well and keeps typography and amounts editable. Composition docs

The current license offers free commercial use for eligible individuals and companies of up to three people; collaborations and organizations of four or more need a company license. Check the actual team arrangement and installed version's terms. Merely putting three friends in a film does not determine eligibility. Pricing and eligibility · Collaboration FAQ

Optional Remotion setup and render commands

Scaffold in a fresh directory outside any Git checkout; the current noninteractive scaffolder rejects an existing repository. This example uses a temporary directory for evaluation. Copy approved source into a durable project afterward; do not depend on temporary files as your archive. Scaffolder docs

cd /tmp
npx create-video --yes --blank kitty-remotion
cd /tmp/kitty-remotion
npm install
npx remotion studio src/index.ts

Ask the agent to create KittyExplainer as a 1920×1080, 30 fps, 2,700-frame composition using the approved scenes. Use useCurrentFrame() and deterministic interpolation; keep assets local and all Remotion packages at the same resolved version. For portrait, create a separate composition layout.

npx remotion still src/index.ts KittyExplainer out/scene.png --frame=450
npx remotion render src/index.ts KittyExplainer out/draft.mp4 --frames=0-149 --scale=0.5 --concurrency=1
npx remotion render src/index.ts KittyExplainer out/kitty.mp4 --codec=h264 --pixel-format=yuv420p --crf=18 --concurrency=1

Start with one render worker on a modest laptop. Increase concurrency only after a successful draft. If memory is tight, the documented --disallow-parallel-encoding flag trades speed for lower memory pressure. Commands follow the render CLI.

For captions, @remotion/captions can parse an SRT file into timed caption objects with parseSrt({input}). The agent still needs to render the active caption at the current frame; parsing does not place words on the video. Use manually checked cues for this short film. Caption parser

Export package

  • Master: 1920×1080, 30 fps, H.264 MP4, yuv420p; AAC audio if present. Keep a 1280×720 draft for quick review.
  • Social version: deliberately rearranged 1080×1920, 30 fps; make a separate 30-second cut from the script rather than merely speeding up the master.
  • Accessibility: readable embedded captions plus UTF-8 SRT/VTT, an HTML transcript and useful poster image.
  • Evidence: source clips and a small HTML/JSON record. Keep verified proof clips separate from the illustrated explainer.
  • Archive: editable scene source, exact dependency lockfile if dependencies were added, fonts/artwork sources and music/voice license notes.

Review the final encoded file on a phone-sized player as well as a laptop. Check it muted, listen once without watching, and inspect the first and last frame of every transition.
